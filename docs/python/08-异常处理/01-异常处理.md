# 8.1 异常处理

一路学到这里，你已经见过一柜子报错了：SyntaxError、NameError、TypeError、ValueError、IndexError、KeyError……每次都是"程序当场死亡，红字刷屏"。这一章做两件事：**教你从容地读懂报错**，以及**让程序出错时不再崩溃**。

## 先学会读报错信息

新手看到满屏红字的第一反应是心慌关掉——大错特错，**报错信息是 Python 给你的诊断书**，里面写着病灶在哪。跑一段会崩的代码：

```python
def get_age():
    text = input("请输入年龄：")
    return int(text)

age = get_age()      # 用户输入了 abc
print(f"你 {age} 岁")
```

用户输入 `abc`，程序崩溃并打印这样一段（这段文字叫 **traceback，回溯信息**）：

```
Traceback (most recent call last):
  File "demo.py", line 5, in <module>
    age = get_age()
  File "demo.py", line 3, in get_age
    return int(text)
ValueError: invalid literal for int() with base 10: 'abc'
```

读法有讲究——**从最后一行往上读**：

1. **最后一行**是诊断结论：`ValueError: invalid literal for int()...'abc'`——错误类型 + 原因（"abc"没法转成整数）
2. **倒数第二组**指着案发现场：`demo.py 第 3 行，get_age 函数里的 return int(text)`
3. 再往上是**调用链**：第 5 行的 `age = get_age()` 调用了出事的函数

一句话口诀：**最后一行看"什么错"，往上找"哪一行"。** 学会读 traceback，一半的 bug 不需要问任何人。

## 崩溃是不可接受的

诊断书能帮开发者改代码里的 bug。但有一类错误**改代码防不住**——用户输入 abc、要打开的文件被删了、网络断了……这些不是你的代码写错了，而是**运行时的外部世界不配合**。总不能用户一输错程序就暴毙吧？

Python 的方案：错误发生时不直接死，而是**抛出一个异常（Exception）**——像裁判扔出一面红旗。你可以选择接住这面旗、按预案处理，程序就能活下去。接旗的语法就是 `try...except`。

## try...except 基本结构

```python
try:
    age = int(input("请输入年龄："))
    print(f"明年你 {age + 1} 岁")
except ValueError:
    print("请输入数字，不要输入其他字符！")

print("程序还活着，继续运行")
```

拆解结构：

```
try:                    ← 试试看：这块代码"可能出事"
    可能出错的代码
except ValueError:      ← 万一出事：出的是 ValueError 就跳到这来
    应对代码
```

执行只有两条路径，务必在脑子里都走一遍：

- **没出错**：try 块顺利跑完 → except 块被完全跳过 → 继续往下
- **出错了**：出错那一行**当场中断**，try 块剩余的代码不再执行 → 跳进匹配的 except 块 → 处理完继续往下，**程序不死**

用上面的例子验证第二条：输入 abc 时，`int()` 抛出 ValueError，`print(f"明年...")` 这行**不会执行**（age 根本没赋上值），直接跳到 except 打印提示，最后"程序还活着"照常输出。

> ⚠️ except 后面的异常类型要**对得上**才接得住。上面的代码若发生的是别种异常（比如 KeyError），这个 `except ValueError` 接不住，程序照样崩。所以关键是预判"这段代码可能出什么错"——好在你早就认识它们了。

## 老朋友点名：常见异常类型

前几章报错速查表里的常客，在这里正式集合。**每一个你都亲手触发过**：

| 异常 | 什么时候发生 | 初次见面 |
|------|--------------|----------|
| `ValueError` | 值不对：`int("abc")` | 2.1 类型转换 |
| `TypeError` | 类型不对：`"a" + 1` | 2.1 数字加字符串 |
| `IndexError` | 越界：`[1, 2][5]` | 2.3 索引 |
| `KeyError` | 字典没这个键 | 4.3 字典取值 |
| `ZeroDivisionError` | 除以零：`10 / 0` | 新面孔，一看就懂 |
| `FileNotFoundError` | 打开不存在的文件 | 7.1 文件操作 |

注意 SyntaxError 不在此列——语法错误在程序**运行前**就被拦下了，轮不到 try 来救，只能改代码。

## 接住多种异常

一段代码可能出好几种错，写多个 except 分别应对，谁发生就走谁：

```python
try:
    a = int(input("被除数："))
    b = int(input("除数："))
    print(a / b)
except ValueError:
    print("必须输入数字")
except ZeroDivisionError:
    print("除数不能为 0")
```

输入 abc 走第一个，输入 0 当除数走第二个——像医院分诊台，什么病挂什么科。

预料不到的错误，用 `Exception` 兜底（它是几乎所有异常的"总类"，什么都接得住），配合 `as e` 拿到具体错误信息：

```python
try:
    # 各种操作
    ...
except ValueError:
    print("必须输入数字")          # 预料中的错，精确处理
except Exception as e:
    print(f"发生了意外错误：{e}")   # 预料外的错，兜底并留下线索
```

> ⚠️ **两条职业操守：**
>
> 1. **能写具体类型就写具体的**。上来就 `except Exception` 一把抓，会把你没预料到的 bug（比如变量名拼错的 NameError）也悄悄按下去，让真正的问题隐身。
> 2. **永远不要写空的 except 然后什么都不做**：
>
> ```python
> try:
>     do_something()
> except:
>     pass        # ❌ 最恶劣的写法：出了任何错都装没看见
> ```
>
> 错误被无声吞掉，程序带病运行，出了问题你连 traceback 都没有——这比崩溃可怕一百倍。至少要打印点什么。

## else 和 finally

完整形态还有两个可选块，用得不多，见到能认识：

```python
try:
    num = int(input("输入数字："))
except ValueError:
    print("输入无效")
else:
    print(f"输入成功：{num}")      # 只有"没出错"才执行
finally:
    print("无论如何都会执行")       # 出不出错都执行，常用于收尾清理
```

四个块的分工一句话：**try 干活，except 救火，else 庆功，finally 打扫。**

## raise：主动抛出异常

异常不只能被动接，还能**主动扔**。当你的函数收到不该收的数据时，与其硬着头皮算出错误结果，不如立刻拉响警报：

```python live_py title=主动抛出异常
def set_age(age):
    if age < 0 or age > 150:
        raise ValueError(f"年龄不合法：{age}")    # 主动抛出，函数就此中断
    print(f"年龄设置为 {age}")

set_age(20)      # 年龄设置为 20
set_age(-5)      # ValueError: 年龄不合法：-5
```

`raise 异常类型("说明文字")` ——这是函数版的"提前 return"，只不过 return 交的是结果，raise 交的是抗议。调用方可以用 try...except 接住这个抗议。**尽早报错、大声报错**，远好过让脏数据混进程序深处再引爆。

## 经典实战：输错就重来

异常处理最高频的实战套路——**用 while True + try 实现"输错重输，直到输对"**（3.2 的 while 和 break 在此重逢）：

```python
while True:
    try:
        age = int(input("请输入年龄："))
        break                        # 能走到这行说明转换成功 → 跳出循环
    except ValueError:
        print("输入无效，请输入数字！")

print(f"你的年龄是 {age}")
```

流程：输入合法 → `int()` 成功 → `break` 出循环；输入非法 → `int()` 抛异常 → `break` 被跳过 → except 打印提示 → 回到循环开头再问一次。用户可以错一百次，程序稳如泰山。

这个模式请形成肌肉记忆，从今往后你写的每个"要用户输数字"的程序都该有它。

## 本章小结

- 读 traceback：**最后一行看什么错，往上找哪一行**——报错是诊断书不是恐吓信
- `try` 放可能出错的代码，`except 类型` 精确接住；出错行当场中断、跳进 except、程序不死
- 多个 except 分诊处理；`except Exception as e` 只作兜底；**永远不吞异常**
- `raise` 主动抛出异常——尽早报错好过带病运行
- **while True + try...except + break** 是输入校验的标准套路，必须形成肌肉记忆
