# 01 部署静态网站

第一个实战：用 Nginx 容器部署一个前端静态网站。以 Docusaurus 文档站为例，React / Vue 项目完全同理（只是构建命令和产物目录不同）。

## 1. 部署思路

静态网站的部署本质就两步：

1. **构建**：把源码编译成一堆静态文件（HTML/CSS/JS）
2. **托管**：用一个 Web 服务器（Nginx）把这些文件伺服出去

用 Docker 多阶段构建，这两步写进同一个 Dockerfile：Node 镜像负责构建，Nginx 镜像负责运行，最终镜像里只有静态文件和 Nginx，非常小。

## 2. 项目结构

```text
my-site/
├── docs/                  # 站点源码（略）
├── src/
├── package.json
├── pnpm-lock.yaml
├── Dockerfile             # 本章新增
├── nginx.conf             # 本章新增
├── .dockerignore          # 本章新增
└── compose.yaml           # 本章新增
```

## 3. 编写 Dockerfile（多阶段构建）

```dockerfile
# ---- 第一阶段：构建静态文件 ----
FROM node:20-alpine AS builder

WORKDIR /app

# 启用 pnpm（Docusaurus 项目用 npm/yarn 的话对应修改）
RUN corepack enable

# 先复制依赖清单，利用缓存
COPY package.json pnpm-lock.yaml ./
RUN pnpm install --frozen-lockfile

# 再复制源码并构建，产物在 /app/build
COPY . .
RUN pnpm build

# ---- 第二阶段：Nginx 托管 ----
FROM nginx:1.25-alpine

# 用自己的配置覆盖默认配置
COPY nginx.conf /etc/nginx/conf.d/default.conf

# 把构建产物拷进 Nginx 的站点目录
COPY --from=builder /app/build /usr/share/nginx/html

EXPOSE 80
```

> React（Vite）项目产物目录是 `dist`，Vue CLI 是 `dist`，把 `COPY --from=builder` 那行的路径改掉即可。

## 4. 编写 nginx.conf

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # 开启 gzip 压缩，明显加快加载
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;

    # 带 hash 的静态资源缓存一年
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 单页应用路由兜底：找不到文件就回 index.html
    # （Docusaurus 是多页静态站可不加；React/Vue SPA 必加）
    location / {
        try_files $uri $uri/index.html /index.html;
    }
}
```

## 5. 编写 .dockerignore

```text
node_modules
build
.docusaurus
.git
*.log
```

`node_modules` 必须排除：它体积巨大，而且容器里会重新安装，宿主机的版本拷进去反而会出问题。

## 6. 编写 compose.yaml

```yaml
services:
  web:
    build: .
    image: my-site:1.0
    restart: unless-stopped
    ports:
      - "80:80"
    logging:
      options:
        max-size: "10m"
        max-file: "3"
```

## 7. 部署与更新

```bash
# 首次部署
docker compose up -d --build

# 验证
docker compose ps
curl -I http://localhost
# 返回 HTTP/1.1 200 OK 即成功

# 以后每次更新内容：拉代码 → 重新构建
git pull
docker compose up -d --build
```

`curl -I` 只看响应头不看正文，成功的输出长这样：

```text
HTTP/1.1 200 OK
Server: nginx/1.25.3
Date: Sun, 18 Oct 2026 10:20:31 GMT
Content-Type: text/html
Last-Modified: Sun, 18 Oct 2026 10:19:05 GMT
Connection: keep-alive
```

看到 `200 OK` 和 `Server: nginx` 就说明 Nginx 容器在正常伺服页面了。

## 8. 常见问题

**构建太慢 / 内存不够**：Node 构建吃内存，1G 内存的小服务器可能直接被 OOM（Out Of Memory，内存耗尽时进程被系统强制终止）杀掉。两种解法：

1. 本地或 CI 里构建好镜像，推到镜像仓库，服务器只 `pull`
2. 本地构建出 `build/` 目录传上服务器，Dockerfile 简化成只有第二阶段：

```dockerfile
FROM nginx:1.25-alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY build /usr/share/nginx/html
```

**访问 404**：确认构建产物目录名对不对（`build` 还是 `dist`），进容器看一眼：

```bash
docker compose exec web ls /usr/share/nginx/html
```

**改了代码但页面没变**：浏览器缓存或没有 `--build`。强刷（Ctrl+F5）并确认部署命令带了 `--build`。

## 动手练习

不借助任何脚手架，手写两个文件把整套流程走通：

1. 新建目录 `my-page/`，写一个 `index.html`（一句 `<h1>Hello Docker</h1>` 即可）和 `style.css`（给 h1 加个颜色），`index.html` 里用 `<link rel="stylesheet" href="style.css">` 引入
2. 参考第 4、6 节写一个最小 `nginx.conf`（要开启 gzip）和 `compose.yaml`，端口用 `8080:80`；这个项目没有构建步骤，Dockerfile 两行就够
3. `docker compose up -d --build` 后浏览器访问 `http://localhost:8080`，样式生效即成功
4. 用 `curl -I -H "Accept-Encoding: gzip" http://localhost:8080/style.css` 验证 gzip 生效（响应头应出现 `Content-Encoding: gzip`）

## 小结

- 静态站部署 = 多阶段构建（Node 构建 + Nginx 托管）
- SPA 项目记得配 `try_files` 路由兜底
- 小内存服务器别在线上构建，本地构建好再上传
- 更新流程固定两条命令：`git pull` + `docker compose up -d --build`
