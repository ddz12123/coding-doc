# 5.1 连接查询与聚合统计

> 本节解决两类高频需求：**跨表查询（JOIN）** 和 **统计分析（COUNT/SUM/AVG + GROUP BY）**。学完你就能写出"每个用户发了几篇文章"这种报表级查询。

> 示例沿用 4.1 节的 User / Post 模型。

## 一、join：跨表过滤

需求："查出张三写的所有文章"。文章表里只有 user_id 没有名字，必须**联合两张表**查询：

```python
from sqlalchemy import select

stmt = (
    select(Post)
    .join(Post.author)              # 沿着关系 JOIN 到 users 表
    .where(User.name == "张三")
)
posts = session.scalars(stmt).all()
```

生成的 SQL：

```sql
SELECT posts.*
FROM posts JOIN users ON users.id = posts.user_id
WHERE users.name = '张三'
```

**推荐沿着 relationship join**（`join(Post.author)`），SQLAlchemy 自动知道 ON 条件。也可以写目标类 `join(User)`（会根据外键自动推断），效果相同。

### join 之后可以随意引用两张表的列

```python
# 查文章标题 + 作者名（两张表的列混合查）
stmt = (
    select(Post.title, User.name)
    .join(Post.author)
    .where(User.name.in_(["张三", "李四"]))
    .order_by(User.name)
)
for title, author_name in session.execute(stmt):
    print(f"{author_name}：《{title}》")
```

### join vs joinedload，别搞混！

| | `.join(...)` | `.options(joinedload(...))` |
|--|-------------|---------------------------|
| 目的 | **过滤/选择**：让 where 能用另一张表的列 | **预加载**：把关系数据装进对象属性 |
| 影响返回内容 | 不装载关联对象 | 装载 `post.author` |

需求是"按作者名过滤**并且**之后要访问 `post.author`"？两个都要写：

```python
stmt = (
    select(Post)
    .join(Post.author)
    .where(User.name == "张三")
    .options(joinedload(Post.author))
)
```

## 二、外连接：outerjoin

`join` 是内连接——"一篇文章都没有的用户"会被丢掉。想保留左表所有行，用 **LEFT OUTER JOIN**：

```python
# 所有用户 + 各自的文章（没文章的用户也要出现，posts 列为 NULL）
stmt = select(User.name, Post.title).outerjoin(User.posts)
for name, title in session.execute(stmt):
    print(name, title)     # 没文章的用户：('王五', None)
```

## 三、聚合函数：func

`func` 是 SQL 函数的万能入口，`func.任意名字` 会原样变成 SQL 函数。以 3.1 节的 5 条种子数据为例（张三 25/北京、李四 30/上海、王五 17/北京、赵六 42/深圳、孙七 28/上海），每行末尾的注释就是它的返回值：

```python
from sqlalchemy import func, select

# 用户总数
session.scalar(select(func.count()).select_from(User))         # 5

# 最大/最小/平均/总和
session.scalar(select(func.max(User.age)))                     # 42
session.scalar(select(func.avg(User.age)))                     # 28.4
session.scalar(select(func.sum(User.age)))                     # 142
session.scalar(select(func.min(User.created_at)))              # 最早一条注册时间（datetime 对象）

# 非重复计数：有多少个不同的城市
session.scalar(select(func.count(User.city.distinct())))       # 3（北京/上海/深圳）
```

## 四、group_by：分组统计

"每个城市有多少用户"：

```python
stmt = (
    select(User.city, func.count(User.id).label("user_count"))
    .group_by(User.city)
    .order_by(func.count(User.id).desc())
)
for city, count in session.execute(stmt):
    print(f"{city}: {count} 人")
```

```sql
SELECT users.city, count(users.id) AS user_count
FROM users GROUP BY users.city
ORDER BY count(users.id) DESC
```

- `.label("别名")` 给计算列起名，结果里可以用 `row.user_count` 访问
- **GROUP BY 铁律**：select 里的非聚合列必须出现在 group_by 里

### having：对分组结果过滤

`where` 过滤的是行，`having` 过滤的是**分组之后的组**：

```python
# 只看用户数超过 2 人的城市
stmt = (
    select(User.city, func.count(User.id).label("cnt"))
    .group_by(User.city)
    .having(func.count(User.id) > 2)
)
```

## 五、组合拳：join + group_by

报表级需求："每个用户发了多少篇文章，按文章数倒序"（以 4.4 节练习的数据为例：张三 2 篇、李四 1 篇、王五 0 篇）：

```python
stmt = (
    select(User.name, func.count(Post.id).label("post_count"))
    .outerjoin(User.posts)                 # outerjoin 保证 0 篇的用户也统计到
    .group_by(User.id)
    .order_by(func.count(Post.id).desc())
)
for name, post_count in session.execute(stmt):
    print(f"{name} 发表了 {post_count} 篇")
# 张三 发表了 2 篇
# 李四 发表了 1 篇
# 王五 发表了 0 篇
```

```sql
SELECT users.name, count(posts.id) AS post_count
FROM users LEFT OUTER JOIN posts ON users.id = posts.user_id
GROUP BY users.id
ORDER BY count(posts.id) DESC
```

## 六、子查询初步

"查文章数超过平均值的用户"这类需求需要**子查询**。入门阶段掌握最常用的一种——把统计结果当临时表再 join：

```python
# 每个用户的文章数（子查询）
post_count_sq = (
    select(Post.user_id, func.count(Post.id).label("cnt"))
    .group_by(Post.user_id)
    .subquery()
)

# 主查询：join 子查询，筛出文章数 >= 2 的用户
stmt = (
    select(User.name, post_count_sq.c.cnt)
    .join(post_count_sq, User.id == post_count_sq.c.user_id)
    .where(post_count_sq.c.cnt >= 2)
)
```

- `.subquery()` 把一条 select 变成"临时表"
- 访问子查询的列用 **`.c.列名`**（c = columns）
- join 子查询时要手动写 ON 条件

子查询是进阶中的进阶，第一遍学习看懂示例即可，用到时回来抄模板。

## 七、常用 SQL 函数速查

```python
func.count(X)、func.sum(X)、func.avg(X)、func.max(X)、func.min(X)   # 聚合
func.now()                        # 当前时间（server_default 常用）
func.coalesce(X, 默认值)          # X 为 NULL 时用默认值（统计时救场神器）
func.length(User.name)            # 字符串长度
func.lower(X) / func.upper(X)     # 大小写转换
func.date(User.created_at)        # 取日期部分（按天分组统计常用）
```

例：按天统计注册量

```python
stmt = (
    select(func.date(User.created_at).label("day"), func.count())
    .group_by(func.date(User.created_at))
    .order_by("day")
)
```

## 🎯 练习

> 前置数据：练习 1、3 沿用 4.4 节练习播种的 rel.db（张三 2 篇、李四 1 篇、王五 0 篇，models.py 为 4.x 章的 User/Post）；练习 2 用 3.1 节的 5 条用户数据（models.py 为 3.x 章的 User，带 city 字段：张三/王五 在北京，李四/孙七 在上海，赵六 在深圳）。

**练习 1：用 outerjoin 找出"从没发过文章"的用户**

用 `outerjoin` + `Post.title.is_(None)` 实现。别用 4.1 节的 `~User.posts.any()`——这次练的就是外连接思路：没文章的用户 LEFT JOIN 过来之后，posts 的列全是 NULL。

<details><summary>参考答案</summary>

```python
from sqlalchemy import select
from models import Post, User, SessionLocal      # 4.x 章的 models.py（rel.db）

with SessionLocal() as session:
    stmt = select(User.name).outerjoin(User.posts).where(Post.title.is_(None))
    print(session.scalars(stmt).all())
```

预期输出：

```text
['王五']
```

思路：`outerjoin(User.posts)` 保留所有用户，没文章的用户其文章各列为 NULL；再用 `Post.title.is_(None)` 把这些行筛出来。顺手记住：判断 NULL 必须用 `is_(None)`，写 `== None` 生成的是 `= NULL`，永远查不出结果。

</details>

**练习 2：统计每个城市的用户数，只保留 ≥2 人的城市**

用 3.1 节的 5 条用户数据（北京 2 人、上海 2 人、深圳 1 人），期望结果只有北京和上海两条。

<details><summary>参考答案</summary>

```python
from sqlalchemy import func, select
from models import User, SessionLocal            # 3.x 章的 models.py（User 带 city）

with SessionLocal() as session:
    stmt = (
        select(User.city, func.count(User.id).label("user_count"))
        .group_by(User.city)
        .having(func.count(User.id) >= 2)        # 过滤"组"用 having，不是 where
    )
    for city, count in session.execute(stmt):
        print(f"{city}: {count} 人")
```

预期输出：

```text
北京: 2 人
上海: 2 人
```

考点：`having` 在分组**之后**过滤，条件里能直接用聚合函数。若误写成 `.where(func.count(...) >= 2)` 会直接报错——where 在分组前执行，那时 count 还没算出来。

</details>

**练习 3：合上书，自己写出"每个用户的文章数倒序"**

不看第五节的模板，凭理解写出：**所有用户**（包括 0 篇的）各自的文章数，按文章数从多到少排列。

<details><summary>参考答案</summary>

```python
from sqlalchemy import func, select
from models import Post, User, SessionLocal      # 4.x 章的 models.py（rel.db）

with SessionLocal() as session:
    stmt = (
        select(User.name, func.count(Post.id).label("post_count"))
        .outerjoin(User.posts)                   # 关键1：用 join 会丢掉 0 篇的王五
        .group_by(User.id)                       # 关键2：按主键分组最严谨
        .order_by(func.count(Post.id).desc())    # 关键3：按聚合结果倒序
    )
    for name, cnt in session.execute(stmt):
        print(f"{name}: {cnt} 篇")
```

预期输出：

```text
张三: 2 篇
李四: 1 篇
王五: 0 篇
```

三个易错点全避开才算掌握：① 写成 `join`（王五整行消失，"所有用户"不成立）；② `group_by(User.name)`——同名用户会被并成一组，按主键 `User.id` 分组才严谨（PostgreSQL/MySQL 认可"按主键分组即可选同表其他列"）；③ 忘写 `.desc()` 变成升序。

</details>

## 📝 本节小结

- 跨表过滤用 `.join(关系)`；要保留无匹配行用 `.outerjoin()`
- `join` 管过滤、`joinedload` 管装载，需求重叠时两个一起写
- 聚合走 `func.count/sum/avg/...`，配 `group_by` 分组、`having` 过滤组、`.label()` 起别名
- "每个X有多少Y" = `outerjoin + group_by` 模板
- 子查询：`.subquery()` + `.c.列名`，先会抄模板
