# 3.4 指针

> 本节目标：理解指针解决什么问题，掌握 `&` 与 `*`、结构体指针、nil 零值，以及指针与值的选择原则。Go 的指针相比 C 已大幅简化。

## 一、先看现象：函数为什么改不动外面的变量

上一节留下的写法：函数想修改结构体，参数写 `*Student`，调用传 `&s`。本节讲清这两个符号背后的原理。先复盘问题：

```go
func addOne(n int) {
    n++                  // 改的是拷贝
}

func main() {
    x := 10
    addOne(x)
    fmt.Println(x)       // 10 —— 没变
}
```

原因第二章讲作用域时就见过：**传参是复制**。`addOne(x)` 时，x 的值 10 被复印一份交给参数 n，函数里 `n++` 改的是复印件，原件 x 毫发无损。

要让函数改到原件，就别把值给它，而是**把"原件放在哪"告诉它**——这就是指针。

## 二、指针是什么：一张写着地址的纸条

变量都住在内存里，每块内存都有编号，叫**地址**。

**指针：存着某个变量地址的变量。**它自己不装数据，装的是"数据在哪"。

一个比喻贯穿本节：传值是把文件**复印**一份给别人，对方怎么改都动不了原件；传指针是把文件的**存放位置**写在纸条上递过去，对方按纸条找到文件，就能真改。**指针就是那张纸条。**

| 概念 | 含义 |
|------|------|
| 地址 | 变量在内存中的位置编号（如 `0xc000012345`） |
| 指针 | 存放地址的变量（那张"纸条"） |
| 传值 | 复制数据交给函数，函数改的是复印件 |
| 传指针 | 把变量的地址交给函数，函数顺着地址改到原件 |

## 三、两个操作符：`&` 和 `*`

指针的全部操作就两个符号：`&` 负责写纸条，`*` 负责按纸条找到原件。

| 操作符 | 读法 | 作用 |
|-------|------|------|
| `&x` | 取地址 | 得到变量 x 的地址（生成一张指向 x 的"纸条"） |
| `*p` | 解引用 | 顺着纸条 p 找到原件（读它或改它） |

### 拆解一下：& 取地址

```
p := &x
     ↑
     取地址 —— 生成一个指向 x 的指针（写一张指向 x 的"纸条"）
```

读作：取 x 的地址，存进 p。此后 p 的类型是 `*int`。

### 拆解一下：* 解引用

```
*p = 99
↑
解引用 —— 顺着 p 里存的地址，找到它指向的变量去读、去写
```

读作：顺着 p 存的地址，操作它指向的那个变量（这里是 x）。

### 拆解一下：指针声明

```
var p *int
      ↑
      *int —— 类型："指向 int 的指针"；这里的 * 是类型写法的一部分
```

读作：声明一个变量 p，它是指向 int 的指针。只声明不赋值时，p == nil（见 六）。

同一个 `*` 出现在两个地方，含义不同。区分口诀：**跟着类型走的是名词，跟着变量走的是动词**。

| 写法 | 这里的 `*` 是 | 读法 |
|------|--------------|------|
| `var p *int` | 名词：类型的一部分 | "指向 int 的指针" |
| `*p = 99` | 动词：解引用 | "解开 p，拿原件" |

### 连起来跑一遍

```go
func main() {
    x := 10

    p := &x               // p 是指向 x 的指针
    fmt.Println(p)        // 0xc000012345 —— 一串地址，每次运行都不同
    fmt.Printf("%T\n", p) // *int
    fmt.Println(*p)       // 10 —— 顺着地址取到 x 的值

    *p = 99               // 顺着地址把 x 改掉
    fmt.Println(x)        // 99 —— x 真的变了
}
```

在脑子里画这张图：

```mermaid
flowchart LR
    x[变量 x] --> vx["10<br/>（地址 0xc000012345）"]
    p[变量 p] --> vp["0xc000012345"]
    vp -.->|"p 里装的不是 10，是 x 的地址（那张纸条）"| vx
```

解读：p 里装的不是 10，而是 x 的地址；`*p` 顺着这个地址访问 x 本体。

## 四、用指针解决开头的问题

一送一收：调用方 `&x` 写好纸条 → 参数 `n` 收到纸条 → `*n++` 按纸条找到原件去改。两个符号配合完成"远程修改"。

```go
func addOne(n *int) {    // 参数类型 *int：我要收的是"纸条"
    *n++                 // 顺着纸条找到原件，加 1
}

func main() {
    x := 10
    addOne(&x)           // 把 x 的地址写成纸条传过去
    fmt.Println(x)       // 11 —— 改到原件了
}
```

## 五、结构体指针：指针 90% 的用武之地

实际开发中，给 int 传指针的场景很少，**指针几乎都用在结构体上**——上一节预告的写法在此展开：

| 写法 | 含义 |
|------|------|
| `func f(s *Student)` | 参数接收结构体指针 |
| `s.Score` | 通过指针访问字段，**自动解引用**，不用写 `(*s).Score` |
| `&Student{Name: "张三"}` | 字面量前加 `&`，创建结构体指针（最常见） |
| `new(Student)` | 创建零值 Student 并返回指针（较少用） |

```go
type Student struct {
    Name  string
    Score float64
}

func addBonus(s *Student, bonus float64) {
    s.Score += bonus     // 注意：直接点，不用写 (*s).Score
}

func main() {
    stu := Student{Name: "张三", Score: 85}
    addBonus(&stu, 5)
    fmt.Println(stu.Score)   // 90
}
```

创建结构体指针的两种写法：

```go
p1 := &Student{Name: "张三"}    // 最常见：字面量前直接加 &
p2 := new(Student)              // new：创建零值 Student 返回指针（较少用）

fmt.Println(p1.Name)            // 张三 —— 照常点
```

结构体指针用起来和结构体本身几乎没差别，唯一的区别是"改了算数"。`&Student{...}` 这个形态以后会大量出现在各种库的用法里（`&http.Server{...}`、`&sql.DB{...}`），现在就熟悉它。

## 六、nil：指针的零值

2.1 零值表中"指针 → nil"那一行在这里兑现：**没指向任何东西的指针就是 nil**。

| 写法 | 含义 |
|------|------|
| `var p *int` | 只声明的指针，p == nil，不指向任何变量 |
| `if p != nil { … }` | 解引用前先判 nil |

```go
var p *int                // 只声明，p == nil
fmt.Println(*p)           // ❌ panic: runtime error: invalid memory address
                          //    or nil pointer dereference
```

防御写法（2.3 的短路求值在此再次配合使用）：

```go
if p != nil {
    fmt.Println(*p)       // 安全
}
```

> ⚠️ **解引用 nil 指针 = 程序当场崩溃**：`nil pointer dereference` 是 Go 程序员见得最多的运行时错误。看到它的条件反射：某个指针没赋值就被使用了。

## 七、指针 vs 值：到底怎么选

新手实用决策表：

| 场景 | 用什么 | 原因 |
|------|-------|------|
| 函数需要**修改**传入的结构体 | 指针 | 传值改不了原件 |
| 结构体**很大**（几十个字段） | 指针 | 免拷贝开销 |
| 小结构体、只读不改 | 值 | 简单安全，没有"被谁改了"的心智负担 |
| int / string / bool 参数 | 值 | 几乎不需要指针 |
| 切片、map 参数 | 值 | **它们本身就是共享语义，别再套指针** |

- `*[]int`、`*map[string]int` 是新手典型的多余写法——切片和 map 传值时数据本来就共享（3.1、3.2 讲过）
- 拿不准时的原则：**结构体传指针，其他传值**，错不到哪去

至此，三章的"复制还是共享"完整版图拼齐了：

| 类型 | 默认行为 | 想共享/修改怎么办 |
|------|---------|------------------|
| 基本类型、数组、结构体 | 复制 | 传指针 `&x` |
| 切片、map | 天然共享 | 什么都不用做 |

## 八、Go 指针 vs C 指针（没学过 C 直接跳过）

Go 的指针做了大量减法，把 C 里最危险的部分全砍了：

| 能力 | Go 的规定 |
|------|-----------|
| 指针运算 | ❌ 没有：`p++` 不存在，不会"走出"变量的地盘 |
| 整数强转成指针乱指内存 | ❌ 不允许 |
| 内存释放 | ✅ 有垃圾回收，不用手动 free，没有悬空指针 |
| 返回局部变量的指针 | ✅ **完全安全**：编译器会自动把它挪到堆上 |

最后一条要特别记住——`return &s` 不但没问题，还是第四章"构造函数"模式的标准姿势：

```go
func newStudent() *Student {
    s := Student{Name: "新同学"}
    return &s        // Go 里完全合法，而且是构造函数的惯用写法
}
```

## 九、常用操作速查

| 需求 | 写法 |
|------|------|
| 取地址 | `p := &x` |
| 解引用（读） | `v := *p` |
| 解引用（写） | `*p = 99` |
| 声明指针 | `var p *int` |
| 判空 | `if p != nil { ... }` |
| 结构体指针访问字段 | `s.Score`（自动解引用） |
| 创建结构体指针 | `&Student{...}` / `new(Student)` |
| 返回指针 | `return &s` |

## 新手常见坑

| 现象 | 原因 | 解决 |
|------|------|------|
| `panic: ... nil pointer dereference` | 解引用了没赋值的指针 | 使用前赋值，或先判 `p != nil` |
| `invalid operation: p++ (non-numeric type *int)` | Go 没有指针运算 | 通过 `*p` 修改指向的值 |
| `cannot use x (variable of type int) as *int value` | 函数要指针你传了值 | 传参加 `&`；反过来就去掉 `&` |
| 函数改了参数，外面没变 | 传的是值不是指针 | 参数改指针类型，调用传 `&` |
| `cannot take the address of 42` | 字面量/常量没有地址 | 先存进变量再取地址 |

## 本节小结

- 指针 = 存地址的变量；**传值复制数据，传指针传递地址**
- 两个符号：`&x` 取地址，`*p` 解引用；类型里的 `*` 是名词（指针类型），表达式里的 `*` 是动词（取原件）
- 结构体指针直接点字段（`s.Score`），Go 自动解引用；`&Student{...}` 是高频形态
- 指针零值是 nil，**解引用 nil 必 panic**——Go 第一大运行时错误
- 选择原则：要修改或结构体大→指针；切片 map 天然共享**不要再套指针**
- 返回局部变量的指针在 Go 里安全且常用（`return &s`）

第三章完成。切片、map、结构体、指针是 Go 日常开发的四大件，后面所有内容都建立在它们之上。
